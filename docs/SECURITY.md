# Security and deployment

## Implemented boundaries

All state lives in one server process. Session IDs and role credentials use independent 256-bit random values. Pairing credentials last two minutes and are atomically consumed once. Credentials appear only in authorization headers or the first WebSocket message; pairing secrets use a URL fragment, removed by the mobile app before exchange. Credentials persist in per-tab sessionStorage for reconnection and are cleared on termination. Remote client URLs require HTTPS/WSS. Loopback-only preview may use HTTP; private upstream HTTP behind an approved HTTPS gateway is supported. Explicit configured origin allowlists protect mutation endpoints, CORS preflights and WebSocket handshakes. Pending phone requests require desktop approval before mobile credentials are issued. No permissive CORS policy is enabled. WebSocket authentication must complete within five seconds; heartbeats run every 15 seconds. Input sizes and option schemas are bounded. Requests are limited to 90 per IP per minute; frames have a one-second minimum interval. In-memory cache/history are capped at 100 questions. No screenshots are written to disk or included in logs. Errors do not log upstream bodies or screenshots.

Question identity includes normalized text and labeled choices, excluding display number. Each explicit Refresh issues a single-use frame request ID, clears the previous result, and starts an eight-second frame delivery deadline. Only the authenticated desktop can consume that request. Duplicate or unsolicited frames are rejected. Generations and cancellation prevent obsolete work from publishing. No automatic frame extraction, screen-change polling, recording or continuous AI processing runs. Mobile snapshots omit questions, other choices, explanations and history. Invalid option selections become uncertain; mismatched question identifiers are rejected. Retry is limited to one retry for HTTP 429/5xx responses, with a per-attempt 25-second timeout. Disconnect/expiry cancels provider work and drops cached questions, history, and all tokens.

The desktop disconnect grace is five seconds; the mobile grace is 20 seconds to allow brief reconnection. Loss of desktop transport immediately invalidates processing and clears the current answer. Capture stops when the desktop receives the termination event or browser capture ends. A disconnected desktop also checks transport state before sending further frames. Network partitions cannot deliver an immediate remote stop event: the desktop must independently enforce the expiration deadline, and browser/tab closure releases its own media tracks.

## Production checklist

- Bind only behind your organization's authenticated gateway. This prototype provides session authentication, not employee identity or organization membership. Enforce SSO and approved employee access before deployment.
- Use one Node process per deployment or sticky routing. Sessions are intentionally ephemeral; multiple replicas require a shared session store and message broker before scaling.
- Set PUBLIC_APP_URL to the exact public HTTPS origin and PUBLIC_API_URL/PUBLIC_WS_URL if separate; keep .env outside image layers and source control. Configure gateway timeouts for WebSockets and up to 55 seconds for inference requests.
- Use a provider and data processing agreement approved for the content. Provider retention is separate from this app's no-disk-storage behavior.
- Do not enable request-body logging at proxies/APM layers. Set a 2 MB proxy body limit. Exclude credentials and QR URLs from analytics.
- Enforce company-approved assessment domain access with managed browser URL policies or an authenticated training portal. Standard screen capture cannot reliably reveal or enforce the origin of an arbitrary selected screen/window. ALLOWED_ASSESSMENT_ORIGINS optionally restricts the supplied desktop client to cooperating tabs exposing a matching Capture Handle origin (the practice app opts in). If configured, unsupported sources/screens/windows fail closed. The server validates the declared origin but cannot attest it against a malicious custom client. This is not a server-verifiable capture allowlist. Consent alone does not prove the selected content is permitted. Do not deploy where domain enforcement is mandatory until an approved source-verification mechanism is implemented.
- The localhost development origin is not usable from a phone. Use a trusted certificate and reachable LAN host; do not disable browser certificate validation.

## Limitations

Analysis is on demand. An answer corresponds to the frame requested by the last Refresh; the application cannot observe subsequent screen changes without another user request. It clears results on Refresh, extraction failure, transport loss, reload and disconnect rather than restoring old suggestions. Vision can still misread text or infer an incorrect answer. Keep the complete question static while Processing is displayed.

There is no background persistence, silent capture, enterprise-policy bypass, cross-frame injection, recording, or extension installation. Enterprise-disabled capture must remain disabled. For strict source enforcement, use an administrator-reviewed integration with the training application rather than arbitrary monitor capture.
